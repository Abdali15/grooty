# Controles y límites

SQL parametrizado, esquema privado, RBAC deny-default en backend, permisos DB acotados y función protegida para autorizaciones; nunca role desde frontend. Identidad estable provider+issuer+subject; correo verificado; tenant Microsoft permitido y sin auto-link por email. Estado navegador y PKCE/nonce de un solo uso; callbacks exactos y HTTPs producción. Sesión opaca aleatoria almacenada por hash, HttpOnly/Secure/SameSite=Lax, sin tokens OAuth persistidos ni localStorage. Logout/revocación real y rol DB consultado por request.

MFA TOTP otpauth, secreto AES-256-GCM con AAD identidad, contador anti-replay, rate limit persistido y caducidad de autorización MFA. La recuperación y rotación son pendientes; perder MFA/key todavía requiere procedimiento operador privado. No confiar en ocultar URL administrativa.

CSRF Origin exacto + token de sesión. JSON limitado; inputs específicos, validación de cantidades/importes/UUID/textos/enlaces. Salida HTML nueva codificada `esc`; frontend existente mantiene escapes. No descargas server-side de referencias/imágenes ni uploads binarios: esa superficie SSRF/path traversal/MIME no se incorpora sin escaneo y almacenamiento privado. Imágenes actuales se muestran desde HTTPS; sigue pendiente validar contenido/licencias/calidad real.

Pagos: importes integer cents derivados de SQL numeric; reserva con product FOR UPDATE ordenado; idempotency advisory lock; transacción atomicidad/journal único. Webhook HMAC con ventana de 5 min y referencia query firmada; se consulta API fija del proveedor (sin URL arbitraria). Se valida receptor, PEN, total, referencia y live_mode=false; no PAN/CVV. Redirect no crea estados. Eventos financieros/stock son append-only para app role. Duplicados aprobados no descuentan dos veces; diferentes pagos reales sobre el mismo pedido necesitan conciliación adicional. Reembolsos/cobros productivos desactivados antes de cerrar recuperación financiera.

Vercel headers/CSP existentes se conservan (script self, sin eval, frame youtube-nocookie, sin clickjacking). Falta probar política en producción con integraciones externas y medir headers de deployment. Cookies/session/JWT en tests locales no certifican configuración cloud. Rate limit DB por identidad, MFA y global OAuth; DoS de visitantes necesita WAF/bot management/monitoring configurados por operador. Pool/timeouts no garantizan disponibilidad ante ataques.

Supply chain: lockfiles y npm ci; advisory alta source-map-js corregida y audits guardados. npm audit solo detecta vulnerabilidades publicadas; no prueba código propio ni garantiza ausencia de ataques. Falta escaneo de secretos/historial con Gitleaks y fijar acciones por SHA validado. No incluir .env, conexiones DB o tokens en ZIP/GitHub. Logs técnicos genéricos y sin respuestas proveedor/códigos OAuth.

ASVS 5.0 usado como referencia de validación/identidad/sesiones/autorización/datos; no afirmar conformidad completa. Revisión independiente y pruebas activas deben limitarse a staging del dueño. No se ejecutó fuzzing contra Google/Microsoft/MP ni carga a producción. Backup/restauración, retención PII, protección de última cuenta ante concurrencia y auditoría fuera del alcance del operador DB necesitan pruebas adicionales.
